# Frontend

`frontend/` is a game-independent SDL2 frontend meant to be shared by the native
recompilation projects. A game plugs in through `fe_game` (`frontend/fe.h`):
ROM validation and loading, reset, DIP words, input bits, one-frame execution
with audio, xRGB555 or xRGB8888 rendering, state save/validate/load, ROM fingerprint and
optional verified gadgets. `ports/sdl2/main.c` is the Dragon Blaze adapter.

| File | Contents |
| --- | --- |
| `fe.h` | public adapter interface |
| `fe_app.c` | window, loop, settings, menus, input, audio, states, rewind, movies, gadgets |
| `fe_draw.c` | embedded font atlas (Inter, OFL) and shapes |
| `fe_platform.c` | UTF-8 paths on Windows/POSIX, directory listing, atomic writes, INI, PNG, log |
| `fe_profile.c`, `fe_profile.h` | JSON game profiles (see below) |
| `assets/fe_font.h` | generated by `tools/make_font.py` |

The interface is original: dark gradient background, a single accent colour
(Azure, Amber, Crimson, Jade, Violet, Silver), animated focus bar, fade-in of each
screen, help line and controls legend. Layout scales from the window size and is
designed for 1280x800 (Steam Deck) and 16:9.

## Menus

Main menu: Resume (when a game is running), Start Game / Start New Game,
Continue (autosave), Load State, Save State (while playing), ROM Selection,
Display, Audio, Controller, Gameplay Settings, Gadgets, Extras, About, Exit.

Quick menu (Esc or the controller shortcut): Resume, Restart Game, Save State,
Load State, Display, Audio, Controller Configuration, Gadgets, Return to Main
Menu, Exit. The game is paused while any menu is open, audio is paused and
flushed, and game inputs are cleared and ignored until released after closing.
Destructive actions ask first.

## Display

| Setting | Values | Default |
| --- | --- | --- |
| Mode | Windowed / borderless fullscreen | windowed (fullscreen on Steam Deck) |
| Window size | 1x-8x native height | 3x (reduced to fit the desktop) |
| Scaling | Fit / Integer (pixel-perfect line height) | Fit |
| Aspect | Original 4:3 / square pixels | 4:3 |
| Filtering | Nearest / bilinear | Nearest |
| VSync | on / off | on |
| Frame pacing | Exact game rate (60.00 Hz for Dragon Blaze) / Display sync (one frame per refresh when the display is 59-61 Hz) | Exact |
| Rotation | 0 / 90 / 180 / 270, the original orientation is marked | 270 (the game's vertical monitor) |
| Scanlines | 0-100% | 0 |
| Phosphor mask | off / aperture grille / shadow mask / slot mask, strength 0-100% | off |
| Brightness, gamma | 50-150%, 0.50-2.00 | 100%, 1.00 |
| Background | black / gradient wallpaper / ambient glow | gradient |

The game always runs at its own rate (60 Hz for Dragon Blaze); the host refresh rate only affects how
often frames are presented. No stretch, crop, widescreen or internal-resolution
option is offered: the board draws a fixed 320x224 picture and widening it would
need content that does not exist.

**Rotation.** Dragon Blaze ran on a vertically mounted 4:3 monitor. The
adapter declares this (`fe_game.rotation = 3`, MAME's ROT270) and the profile
repeats it (`display.rotation: 270`), so the picture, the window shape, menu
previews, slot thumbnails and saved screenshots are all upright by default.
Choose 0 for a monitor that is physically turned, or 90 for one turned the
other way. The
`--rotate N` command line option overrides the setting for one session. **Curvature is not implemented**: SDL_Renderer
has no programmable shaders, and a CPU remap at output resolution would cost more
than the whole game. CRT effects are done with overlay textures (scanlines alpha,
phosphor mask multiply).

## Audio

Master volume, mute, output device, latency target (16-250 ms). The YMF278B's
mono output is produced at the chip's rate (28.63635 MHz / 768 = 37,286 Hz,
as in MAME) and resampled by SDL to the output device. Latency is
bounded: if the queue grows beyond twice the target (after a stall), the excess
chunk is dropped and counted rather than letting delay accumulate. Underruns and
drops are shown in Audio > Diagnostics and logged at exit. Separate music/effects
volume is not offered: music and effects are mixed inside the YMF278B (FM and
wavetable channels share one output), so there is no separate signal to
control.

## Gadgets

FPS, frame time (CPU time of one game frame), input display (both players'
inputs), and the two players' scores. Each can be enabled, placed in one of
six anchors, fine-offset and sized. The score addresses (0x06070F34 and
0x0607123C, 32-bit) were matched against the in-game HUD in MAME reference
runs of a one- and a two-player game; they are the only work-RAM words that
match at every checked frame. Lives, bombs and stage are not offered: their
addresses were not verified, and an unverified gadget would show wrong
numbers.

## Players and controllers

Up to four players are supported by the frontend (`fe_game.players`); Dragon Blaze
uses two. Controller Settings > Player Controllers assigns a connected
controller to each player (automatic by default: first pad = P1, second = P2).

## NVRAM

Games that provide `nvram_save`/`nvram_load` get a file in `nvram/` in the data
folder, named `<id>-<ROM fingerprint>.nv`. It is restored right after the ROM is
loaded, saved when the game writes it (checked every 2 s), when a game ends and at
exit. For Dragon Blaze this is the board's 256-byte 93C56 EEPROM: test-menu
settings, bookkeeping and high scores (same layout as MAME's
`nvram/dragnblz/eeprom`). Save states also include it.

## Game profiles (JSON)

`profiles/<id>.json` describes a game's identity, presentation preferences and
the frontend features it asks for. The frontend looks for it, in order: the
`--profile FILE` argument, `<data folder>/profiles/`, `profiles/` next to the
executable, then `../share/<id>/profiles/` (AppImage layout).

A profile never enables anything on its own. Each requested feature is combined
with what the adapter actually implements; the outcome for every feature is
written to `frontend.log` and shown on the About screen:

| Feature | Supported when the adapter provides |
| --- | --- |
| `save_states`, `rewind`, `input_movies` | `save_state`, `validate_state` and `load_state` |
| `nvram` | `nvram_save` and `nvram_load` |
| `gadgets`, `input_display`, `screenshots` | always |
| `widescreen` | never (no adapter can widen a fixed arcade picture) |

A feature set to `false` is switched off even when supported (its menu entries are
hidden or disabled). Identity fields (`title`, `subtitle`, `rom_hint`) and
`display.aspect` (`"4:3"` or a number) and `display.rotation` (0, 90, 180, 270:
the original orientation) override the adapter's values; `players` is checked
against the adapter and reported if it disagrees. A profile with a different `id`, a syntax error or out-of-range values
is ignored (with the reason in the log) and the adapter defaults are used.

## Extras

Rewind (bounded memory), autosave on exit / on main menu, pause when unfocused,
record / play input movies, screenshot, data folder location, reset all settings.

## Files

`settings.ini`, `frontend.log`, `states/`, `nvram/`, `screenshots/`, `movies/` in the data
folder (see `docs/SAVE_STATES.md`). Set `FE_PROFILE=1` to log loop, present and
frame times every 120 frames.

## Command line

```
--rom PATH        ROM archive (also: drag it onto the executable)
--rotate N        picture rotation in quarter turns for this session
--fullscreen / --windowed
--scale N         window multiple
--window WxH      exact window size (1280x800 previews the Deck)
--portable        data beside the executable
--state FILE      load a .fest file at start
--no-menu         start the game immediately
--frames N        quit after N frames (automation)
--screenshot FILE PNG of the last frame at exit (unrotated, as the board outputs it)
--profile FILE    use this game profile instead of profiles/<id>.json
```
